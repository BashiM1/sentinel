=== The bug ===
Two sibling Its under Context("Job success path") both used the constant
`name = "lifecycle-success"`. Cleanup after It #1 deleted the CR and its
Job. BeforeEach for It #2 created a new CR with the same name (different
UID) and driveToScanning created a new Job (different name, same label).

But the test helper was:

    func listOwnedJobs(ctx context.Context, scanName, namespace string) []batchv1.Job {
        var jobs batchv1.JobList
        k8sClient.List(ctx, &jobs,
            client.InNamespace(namespace),
            client.MatchingLabels{LabelGovernanceScan: scanName},
        )
        return jobs.Items
    }

Under coverage instrumentation, goroutine scheduling shifted enough that
a leftover Job from It #1 occasionally still existed when It #2 listed
jobs — so `jobs[0]` was the *previous* test's Job, the one already marked
Complete. markJobComplete operated on an already-complete Job (no-op in
the apiserver's eyes), and the actual current Job stayed in Scanning.

=== The production code already filtered by UID ===
// internal/controller/job.go — production findOwnedJob
for _, owner := range job.OwnerReferences {
    if owner.UID == scan.UID {
        return job, nil   // <-- this UID check is what tests were missing
    }
}

=== Fix ===
Renamed listOwnedJobs to take scanUID and filter by it (mirrors
production). Added listJobsByLabel for cleanup-only use where UID is
no longer available. Cleanup now uses DeletePropagationBackground and
asserts BeEmpty() after, so any future leak fails fast.

Result: 12/12 specs pass under both `go test` and `make test`.
